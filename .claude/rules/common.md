# common

- yagni を意識する
  - ただし、ツールの暗黙の既定挙動に依存して設定を省かない。重複に見えても意図が読み取れるよう明示する(例: gitignore 済みのパスは prettier / editorconfig-checker も自動で除外されるが、`.prettierignore` / `.ecrc` にも明示する)
- dry を意識する
  - リポジトリ内の複数箇所(`.env.example`、CI workflow の `env`、README、テストヘルパー等)で同じ値を持つもの(テスト用の固定値、環境変数の既定値等)を変更するときは、変更前の値をリポジトリ全体で検索し、追随漏れが無いことを確認する
    - ローカルの `.env` は変更後の値を持つため、この種のズレはローカルのテストでは検出できず CI でしか表面化しない。ローカルのテストが通ったことは確認の根拠にならない
- early return を意識する
- 型安全を意識する
- testable を意識する
  - 外部 SDK/ライブラリの型をそのまま流用すると、fake/mock を使ったテストに型アサーションが必要になり testable でなくなることがある。その場合は型アサーションで回避せず、実際に使うプロパティだけの最小構造型を自前定義できないか先に検討する
- 順序に意味を持たない array, object, リスト(.gitignore, .prettierignore 等)は alphabetical order にする
  - 順序に意味がある場合(否定パターンの前後関係、マージ時の上書き優先順位など)は対象外
  - コメント等で意図的にグルーピングされている場合はグループ単位を保ったまま、グループ内で alphabetical order にする
- 外部の共有リソース(DB、GCS バケット等)に書き込みうる、または対象リソースのスキーマ/状態を変更しうるコマンドを実行する前に、対象の環境変数(`DB_POSTGRES_URL`、`BUCKET` 等)が実際にどこを指しているかを確認する。プロセス/コンテナが起動していることの確認は、環境変数がそのプロセスを指している証明にはならない
